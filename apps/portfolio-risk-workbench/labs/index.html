01 · Outcome
What should be different when this agent finishes?
Start from a governed recipe or describe the job. Both produce the same reviewable blueprint.

              
Understand this step and every option
Recipe supplies a coherent starting pattern: prompts, state, routing, capabilities, governance and output design. Selecting one does not publish an agent; it creates an editable draft.
Agent name identifies a reusable job, not a single run. Observable outcome describes the artifact or change a reviewer can verify after completion. Prefer “create a cited Event Risk Brief” over personality instructions such as “be a brilliant analyst.”
Draft with AI compiles the description into the existing strict blueprint. It can suggest registered options but cannot enable portfolio effects or unknown capabilities.

              

              

                
                
              

              

                
                
              

            


            

              
02 · Trigger and scope
When does it run, and what may it work on?
The current prototype records these invocation rules for the workflow. Scheduling remains controlled by the workflow runtime.

              
Understand triggers, scope, time and duplicate handling
Trigger describes who starts the assignment: a person, workflow cycle, eligible event, or schedule. It does not grant authority. Scope limits the portfolio, experiment or dataset the assignment may address.
As-of rule is the information boundary. Workflow date suits periodic replay; event availability time prevents an event agent from seeing information before ingestion; assignment time is useful for manually commissioned analysis.
Duplicate handling makes repeated delivery safe. It identifies when two requests should resolve to the same logical piece of work instead of creating duplicate reviews.

              

              

                
                
                
                
              

              
Compiled boundary

            


            

              
03 · Context and capabilities
Which reviewed information and operations may it use?
Packs are named presets over the existing input contract and capability latches.

              
Understand context and capability packs
Context Pack controls which reviewed information is supplied and under which point-in-time boundary. It is the agent’s readable evidence envelope—not unrestricted database access.
Capability Pack is the allow-list of registered operations the agent may request. Market data reads observations; risk metrics reads deterministic MetricPack values; portfolio exposure calculates concentration; scenario stress applies bounded shocks; event retrieval reads eligible events; the evidence critic checks claims.
A capability permits an operation but never grants portfolio authority. Advanced mode exposes invocation conditions, output bindings, requirements and failure policies for every latch.

              

              

                
                
              

              
Granted operations

              
            


            

              
04 · Output and authority
What must it return, and where must it stop?
The rendered artifact stays machine-readable underneath. Portfolio effects remain locked off.

              
Understand output contracts and authority
Risk Review Draft is a human-facing decision-support review. Specialist Interpretation is a bounded analytical contribution. Evidence Critique audits claims and temporal eligibility. Capability Request records why the current grants are insufficient without inventing a tool.
A1 drafts from supplied context and uses only evidence validation. A2 may call the displayed effect-free analytical capabilities. Both stop at human review and both permanently deny trading, hedging, rebalancing, broker contact and portfolio mutation.
Selecting an Output Contract regenerates a matching strict schema. Advanced mode can then define fields, validations, rendering, charts, tables and multi-pass assembly.

05 · Test and save
Is this version safe and useful on representative cases?
A quick gate checks the contract, an ordinary case, a failure boundary, and an adversarial evidence case.

              
Understand validation, testing and saved runs
Validate checks schema coherence, capability allow-lists, prompt variables, state, routing, output production and locked effects. It does not judge analytical usefulness.
Representative test checks normal work. Failure boundary checks missing evidence and abstention or escalation. Adversarial test confirms untrusted content cannot alter governance. A quick pass supports iteration; historical replay and reviewer thresholds are still required for research certification.
The Run Review page distinguishes code-generated behavior samples from real DuckDB data, freezes the exact input, records the work log and stores every output in a run-specific local folder.
