## Frozen Phase 2 boundary

- One integration owner and three parallel read-only audits: contracts and
  persistence, existing-run migration, and repository UI/policy.
- Generated bytes remain external to Git and are addressed by content digest.
- Repository metadata adapts existing artifact references; it does not redefine
  business objects or make run files authoritative for agent/workflow meaning.
- Existing run admission is opt-in and previewed.
- No automatic cleanup daemon is introduced.
- Ordinary deletion uses an explicit consequence preview and confirmation,
  seven-day recoverable tombstone, reference checks, and finalization only
  after the recovery deadline.
- Published and evidence-locked material denies ordinary deletion.
- No experiment scheduler, report composer, decision system, Studio–Codex
  execution, provider integration, or financial effect is in scope.

## Deviations, limitations, and rollback

The initial sandboxed preflight could not resolve the package index; the exact
same pinned command passed with network approval. Browser QA used only a
temporary synthetic artifact root. No user run was admitted, rewritten or
deleted during implementation or acceptance.

This is development-local persistence, not production object storage,
deployment, publication, scheduling or automatic cleanup. A corrupt committed
catalogue fails closed pending a later explicit maintenance procedure. The OS
account remains inside the local trust boundary.

Rollback is removal of the Phase 2 worktree/branch and restoration of the
current programme pointer to accepted Phase 1. Mutable repository state remains
outside Git and must be handled separately under its lifecycle policy.
